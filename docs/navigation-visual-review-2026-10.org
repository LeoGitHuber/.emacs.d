#+title: 导航界面多场景审美评审
#+date: 2026-10-18

* 评审方法
由一个不继承主对话历史的独立 agent 查看真实 GUI，逐场景评价。
场景使用加载完整配置的独立实例和临时项目，覆盖不同文件数量、窗口布局、
正文类型与主题。GNU Emacs 为 32.0.50，NeoEmacs 为 31.1。
评分重点是可读性、焦点辨识、信息层级和空间分配；颜色喜好单独记录。

首轮完整检查 GNU 的 17 个场景、Neo 的 5 个代表场景。
Neo 的深层目录场景构造报错，未计入完成数量。
后续对照将 Neo 扩展至 8 类：深色代码、浅色 Org、拥挤文件、窄窗、
分屏左侧、分屏右侧、目录树获焦和 Matrix。

* 首轮逐场景发现
| 场景 | GNU 评价 | Neo 首轮评价 |
|------+----------+---------------|

| 四层深目录、长 TSX 文件名 | 目录层级清楚，但树和文件标签都截掉名称尾部 | 构造失败，未完成评价 |

| Matrix | 非当前标签和关闭按钮过暗；树标题灰底与绿色标签栏不一致 | 首轮未单独评价 |
| 单工作区、单文件 | 两层导航略重，属于偏好问题 | 首轮未单独评价 |
| 空工作区 | 文件标签正常消失，布局干净 | 首轮未单独评价 |
| 窄窗口隐藏目录树 | 正文空间恢复；标签仍保留旧横向滚动位置，右侧浪费空间 | 首轮未单独评价 |
| 放大 Org 正文 | 正文层次清楚；导航字体也变大，与侧栏失衡 | 首轮未单独评价 |

* 本轮修改
- 导航固定等宽字体和字号，保留正文的混合字体与缩放功能。
- 从主题正文前景和背景混合生成导航底色、次级文字色和窗口分隔色。
  Matrix 不再直接使用过暗的 shadow 作为非当前标签文字色。
  原生关闭、修改状态、滚动按钮也同步更新前景，保留原有 SVG 与点击行为。
- 文件标签使用原生的活动、非活动窗口 face 区分焦点；工作区减少彩色强调。
- Neo 使用原生文件标签 face 扩展接口，根据命令完成后的实际窗口焦点选择 face。
  这是针对 Neo 当前标签未高亮的兼容处理，GNU 使用原生判断。
- 文件标签按编辑窗口宽度缩短，保留名称尾部；中文名称按显示列数截断。
  当前文件可使用更多宽度，让 config.json<server> 一类短名称保持完整。
- 窗口宽度变化时重算原生文件标签，清除旧横向滚动位置。
  未改变窗口宽度时保留用户手动滚动位置。
- 工作区名称采用中间省略，保留相似名称末尾的区别，再交给原生自动宽度；
  最前面的补白保留普通空格，避免复制 display 空格
  时相邻显示属性合并，导致自动宽度的填充循环不能结束。
- 新打开的目录树按 frame 宽度取 20–32 列，窗口之间启用 1 像素原生分隔线。
  主题刷新后重新启用分隔，避免主题的自定义变量关闭它。
- 目录树标题同时适配 header-line 的活动、非活动 face。

* GNU 修改后的独立复查
| 场景 | 复查结果 |
|------+----------|
| 深色代码 | 工作区改为中性色，当前文件使用强调色，两级导航更清楚 |
| 浅色 Org、放大正文 | 正文变衬线或放大时，工作区和文件标签保持相同等宽字号 |
| Matrix | 非当前标签、关闭按钮清楚可读，树标题不再残留灰底 |
| 分屏左侧、右侧、树获焦 | 强调色随编辑焦点移动；树获焦时两个编辑标签都降为普通色 |
| 拥挤文件标签 | 可见数量从三项增至四项，长名称的区别尾部更清楚 |
| 窄窗口 | 树从约 272 像素减至 216 像素；标签从两项增至三项，当前 config.json<server> 完整 |
| 窄窗口隐藏树 | 标签重排，原先保留的横向滚动和大块空白减少 |
| 八个工作区 | 保持单行，navigation 与 experiments 的区别尾部可辨 |
| 底部编译面板 | 树底部细横线实际可见，输出面板与树分开 |

仍保留的低优先级取舍：原生工作区自动宽度会让短名后留空白；拥挤时关闭按钮
与文字略紧。它们属于布局偏好，没有继续叠加定制渲染。

* Neo 最后补丁后的独立复查
重启独立实例加载完整的新配置，再检查浅色阅读、左右及目录树三种焦点和 Matrix。
当前阅读文件恢复主题强调色；左右编辑窗强调色随焦点正确切换，目录树获焦后
编辑标签降为普通色；Matrix 次级文字和关闭按钮清楚可读。

窄窗的树宽和标签密度在上一轮已确认改善，最后的小幅当前标签预算调整只在
GNU 完整复验。不能把 GNU 的全部视觉结论直接等同于 Neo 的验证结果。

* 边界与后续检查
窄窗口仍不可能同时显示所有文件；可以通过原生标签滚动、C-x b 和 F8 调整空间。
目录树宽度在打开时决定，保留手动调整结果。单文件仍保留工作区和文件两级导航，
避免随文件数量变化而跳动布局。

Neo 的目录刷新、子级缩进、连接线与 GNU 存在差异。程序化建树后的缺字可通过
F8 关开恢复，但这不能证明日常使用一定出现相同问题。深层目录场景需要单独验证。
本轮没有修改 Dirvish、Tabspaces 或其他第三方子模块源码。

临时 Org 场景还出现 Valign 的 “End of table goes backwards” 提示。
本轮没有定位或修复该表格对齐问题，不能将它算入已通过的导航检查。
Neo 的 Shift+Tab 键映射差异也保留为后续检查项。

* 验证
配置测试覆盖项目隔离、分屏打开目标、文件标签顺序、主题切换、长中文文件名
区别段保留、窗口变宽后的标签重排、Neo 焦点 face 和主题关闭分隔线后的恢复。
GNU Emacs 与 NeoEmacs 各通过 27 项配置测试。所有本轮配置文件保持 LF。
视觉结论以独立 agent 的实际 GUI 复查为准。

* 2026-10-20 后续调整
根据实际使用反馈，移除导航补白中 1.6 倍高度与固定 ascent 的 display 属性，
改为普通空格，让工作区、文件标签和目录标题的高度由字体自然决定。
上述多场景视觉评审记录对应调整前的版本；本次只收紧高度。

* 2026-10-20 单行导航调整与复查
后续按用户选择，将文件和工作区合并到同一条原生 tab-bar：
左侧显示最近编辑窗口的文件，最右侧仅显示当前工作区，点击展开全部工作区。
关闭各编辑窗口的 tab-line 显示，保留它的文件顺序和 Ctrl+Tab 切换逻辑。
删除不再需要的窗口宽度重排钩子及 Neo 专用 tab-line 焦点 face 补丁。
本节取代前文关于“两层导航”和上述补丁的现状描述，前面的表格保留为历史记录。

本次由主 agent 在独立临时 GUI 实例中复查，未把旧版审美评分套用到新布局：

| 版本与场景 | 观察结果 |
|------------+----------|
| GNU 深色代码 | 顶部一行，文件靠左、当前工作区靠右，字体自然高度 |
| GNU 工作区菜单与空工作区 | 菜单可切换到 Default；空工作区左侧不显示无关 buffer |

两个版本各通过 28 项配置测试，包括 40、60、100、150 列的标签宽度预算、
完整工作区名称选择和侧栏获焦时的文件点击目标。相关文件保持 LF。

* 2026-10-25 旧会话恢复产生重复标签
实际 Desktop 会话仍保存了 buffer 的 =tab-line-mode=；它在 init 关闭全局模式后
重新启用局部模式，导致上下两排显示同一个文件。之前的新会话测试遗漏了此路径。
通过 =desktop-minor-mode-handlers= 忽略旧条目，并通过 =desktop-minor-mode-table=
阻止新会话保存该模式，无需额外 advice 或刷新钩子，也无需删除用户会话。

GNU Emacs GUI 使用相同 Desktop 文件恢复入口，复现双排标签后验证修复为单排。
新增测试覆盖旧条目恢复及后续保存，并确认其他 minor mode 仍可正常恢复与保存。
GNU Emacs 全部 30 项配置测试通过。按用户要求，自本次起仅验证 GNU Emacs，
不再测试或处理 NeoEmacs 兼容问题；前面的双版本结果保留为历史记录。
